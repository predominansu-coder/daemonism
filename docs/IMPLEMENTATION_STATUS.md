## 2. 인터페이스가 실제 완성 기능과 다른 부분

- `notify_player_action_applied()`와 행동 수락 여부는 존재하지만 Q/E를 실제 실행하는 시스템은 없습니다.
- 패턴의 `projectile_contact`는 미래 피해 수신 지점이며 현재 HP 감소·피격·사망을 하지 않습니다.
- `enemy_ids`는 콘텐츠의 적 종류 목록이며 살아 있는 적별 런타임 상태나 다수 적 타깃 선택을 제공하지 않습니다.
- `WorldState` 플래그/카운터/결과 저장 기반은 있지만 조건/효과 해석기, 전투 결과 중복 반영 방지, 지역별 재등장 정책은 아직 없습니다.
- `SaveManager`의 섹션/버전 검증은 존재하지만 이전 버전 이행, 현재 맵/위치/성장/퀘스트의 전체 진행 저장, 체크포인트 복구를 구현한 것은 아닙니다.
- 사용자 정의 패턴 실행기 계약을 검증했지만 본편 보스 콘텐츠나 모든 패턴 조합을 구현·검증하지 않았습니다.

현재 아레나는 원점·회전 없음·스케일 1이 전제이며, 임의 변환을 적용하는 재사용은 좌표 변환 계약을 추가하기 전까지 지원하지 않습니다.

## 5. 다음 개발 순서

1. Windows Godot 4.7.2에서 화면·방향키·Space·예고·게이지·복귀를 확인하고 사용감/카메라 수치를 조정합니다. 행동 단계 조작 정책을 실제 행동 시스템 구현 전에 결정합니다.
2. 적별 런타임 상태·살아 있는 대상 선택·Q 범위 검증/피해와 플레이어 피해 수신/HP를 작은 정식 단위로 추가합니다. 필드/전투 능력을 공유할 경우 먼저 공유 규칙을 결정합니다.
3. E 시간 UX를 사용자와 결정한 뒤 조건부 선택지·효과·완료 계약을 연결합니다. 메뉴 열기만으로 소비하지 않습니다.
4. 조우/적별 결과 확정과 중복 적용 방지, 세계 상태·성장·필드 재등장 정책을 분리해 연결합니다.
5. 사망 후 유지/복구 범위를 결정하고 사망 연출·게임오버·체크포인트를 수동 저장과 분리해 구현합니다.
6. 실제 진행 시스템이 늘어날 때 저장 섹션·버전 이행·이야기 조건/효과와 콘텐츠를 확장합니다.

이 순서는 실행 가능한 기반을 단계적으로 확장하는 계획입니다. 아직 구현하지 않은 30시간 RPG 전체 체계가 완성됐다는 선언이 아닙니다.
