# DAEMONISM 전투 기반 계약

기준: 2026-10-16 현재 구현. 확정 기획과 잠정값은 [아키텍처 기준](ARCHITECTURE_BASELINE.md), 실제 검사 결과는 [구현 현황](IMPLEMENTATION_STATUS.md)을 참조합니다. 과거 Step 03 단계 코어는 이미 저장소에 있으며, 이번 개발은 이를 아레나·플레이어·패턴 실행과 연결합니다.

## 1. 전투 조립

```text
GameRoot → CombatScene (조우 문맥·신호 연결·개발용 HUD)
             ├─ CombatDirector
             │    └─ AttackPhaseGate
             ├─ Arena (CombatArena, 경계·벽)
             │    ├─ Player (CombatPlayer)
             │    ├─ PatternRunner (AttackPatternRunner)
             │    │    └─ 실행 중 AttackPatternExecutor
             │    └─ Camera2D (플레이어를 따라가지 않음)
             └─ HUD (CanvasLayer, 상단 행동 게이지 등)
```

`CombatScene`은 조립 지점입니다. 감독은 적 이름이나 공격 알고리즘을 모르며, UI는 감독의 시간 신호를 표시합니다. 전투 카메라는 아레나 중심에 고정되고 창 크기에 맞춰 영역을 담도록 확대율을 조정합니다. 벽 충돌과 플레이어 반지름을 고려한 경계 제한을 함께 사용합니다. 현재 공간·도형·크기는 개발용입니다.

현재 아레나는 **원점·회전 없음·스케일 1**을 전제로 합니다. 플레이어 경계는 월드 좌표, 패턴 경계는 아레나 로컬 좌표로 전달하므로 아레나를 이동·회전·확대하려면 먼저 좌표 변환 계약을 추가해야 합니다.

## 2. 데이터와 실행 상태

| 정의/설정 | 현재 담당 데이터 | 실행 시 소유자 |
| --- | --- | --- |
| `EncounterDefinition` | 조우 ID, 적 종류 목록, `CombatTiming`, `AttackPatternDefinition` | `CombatScene`이 참조. 현재 적별 HP 인스턴스는 없음 |
| `EncounterRequest` | 이번 조우의 정의 참조, 지역·배치 ID | `GameRoot`와 해당 전투. 영속 저장이 아님 |
| `CombatTiming` | 공격 종료 방식, 공격시간, 행동시간 N | 감독/종료 게이트가 잔여시간 소유 |
| `PlayerMotionSettings` | 이동속도, 대쉬속도·지속시간·쿨타임 | `CombatPlayer`가 방향·남은 시간·쿨타임 소유 |
| `AttackPatternDefinition` | 예고·발사·투사체 수치, 선택적 사용자 정의 실행기 씬 | 실행기가 발사 진행·예고·살아 있는 투사체 소유 |

공유 Resource를 실행 상태 저장소로 사용하지 않습니다. `dev_player_motion.tres`, `dev_attack_pattern.tres`, `dev_combat_timing.tres`의 값은 편집 가능한 예시입니다. 새 적 종류 목록을 입력하는 것만으로 다수 적의 개별 AI/HP/타깃이 생성되지는 않습니다.

## 3. 단계 감독

`CombatDirector`는 `IDLE → ENEMY_ATTACK ↔ PLAYER_ACTION`과 `FINISHED`를 소유합니다.

1. 유효한 시간 데이터로 `begin()`하면 공격 주기를 새로 만들고 종료 게이트를 먼저 준비한 뒤 단계 신호를 보냅니다.
2. 공격 진입 시 장면은 이전 실행기를 중지하고 이번 패턴을 시작합니다.
3. `DURATION`은 설정된 공격시간 뒤 행동 단계로 갑니다. 패턴이 먼저 끝나도 시간을 단축하지 않으며, 시간이 먼저 끝나면 남은 예고·투사체를 정리합니다.
4. `SEQUENCE_FINISHED`는 실행기의 유한 시퀀스 완료를 기다립니다. 설정된 공격시간만으로 종료되지 않습니다.
5. 행동 단계는 N초를 감소시키며 UI 신호를 보냅니다. 실제 적용된 행동 한 번 또는 시간 초과 후 다음 공격 주기로 갑니다.
6. `stop()`/`finish_encounter()`는 현재 주기를 무효화합니다. 재진입한 신호 수신자가 전투를 중지·종료한 경우도 이전 콜백이 다음 공격을 다시 시작하지 않도록 확인합니다.

외부 패턴은 `director.report_attack_sequence_finished(cycle)`을 통해 완료를 알립니다. 전달 주기가 현재 `attack_cycle`과 같고 현재 시퀀스 방식의 공격 단계일 때만 수락합니다. 실행기 runner도 별도 generation으로 교체된 실행기의 늦은 신호를 차단합니다. `AttackPhaseGate`의 저수준 완료 메서드를 패턴에서 직접 호출해 토큰 검사를 우회하지 않습니다.

시간 기반 조우는 예전처럼 패턴 없이 구성할 수 있습니다. 시퀀스 방식에는 패턴이 필수입니다. 현재 개발 조우의 기본값은 시간 기반입니다.

## 4. 이동과 무적 없는 대쉬

`CombatPlayer`는 필드의 `actors/player/player.gd`를 바꾸거나 상속으로 억지 결합하지 않은 전투 전용 `CharacterBody2D`입니다. 공통 입력 액션 `move_*`만 재사용하고 전투 카메라는 아레나가 소유합니다.

- 방향키 이동 벡터를 사용해 대각선 속도가 증가하지 않습니다.
- Space(`combat_dash`)는 이번 개발용 키입니다. 이동 입력 방향, 또는 입력이 없으면 마지막 방향으로 대쉬합니다.
- 수락한 순간 쿨타임이 시작되며 대쉬 도중/쿨타임 중 재요청을 거절합니다. 마지막 물리 프레임에는 남은 지속시간만큼 이동합니다.
- 벽·아레나 경계에서 멈추고, 조작을 끄면 진행 중 대쉬도 종료합니다.
- 대쉬 동안 일반 충돌과 투사체 접촉을 유지합니다. 무적 상태를 만들거나 접촉을 무시하지 않습니다.
- 현재 **공격/행동 단계 모두 이동·대쉬 허용은 개발용 동작**입니다. 행동 단계 정책과 필드/전투 능력 공유는 미정입니다.

## 5. 패턴 실행과 종료 수명

기본 `VolleyPatternExecutor`는 아레나 내 지정 원점에서 플레이어를 향해 방향을 잡고 예고선을 표시합니다. **예고가 시작될 때 발사 방향이 고정**되므로 플레이어가 이동해 피할 수 있습니다. 예고 후 부채꼴 투사체를 발사하고 설정 횟수만큼 반복합니다. 이는 개발 패턴이며 모든 향후 적 조합의 회피 가능성이나 정식 난이도를 검증한 것은 아닙니다.

`AttackPatternExecutor`는 예고와 투사체를 소유합니다. 마지막 발사 직후에는 완료를 알리지 않습니다. 발사를 마쳤고 모든 소유 투사체가 접촉·영역 이탈·수명 만료로 퇴장한 뒤에만 `sequence_finished`를 내보냅니다. 단계 변경·복귀·장면 제거 시 `stop()`은 공격체를 비활성화하고 정리합니다.

특수 패턴 확장:

1. `AttackPatternExecutor`를 상속한 스크립트를 루트로 사용하는 `PackedScene`을 만듭니다.
2. `AttackPatternDefinition.executor_scene`에 연결합니다. runner는 인스턴스가 올바른 기반 클래스를 상속했는지 검사합니다.
3. `_begin_pattern()`, `_advance_pattern(delta)`를 구현합니다. 제공된 `show_telegraph()`, `spawn_projectile()` 헬퍼를 사용하고 유한 발사가 끝나면 `finish_emission()`을 호출합니다.
4. 별도 공격체·타이머·비동기 작업을 추가한다면 완료 시점에 남은 위험이 없고 `stop()` 이후 효과가 발생하지 않도록 해당 실행기가 책임집니다. 기본 클래스가 추적하는 것은 제공 헬퍼로 생성한 공격체입니다.
5. 정상 완료뿐 아니라 중간 취소·재시작·늦은 신호·마지막 공격체 수명에 대한 검증을 추가합니다.

현재 구현은 이 확장 계약과 기본 일제사격을 제공합니다. 완성된 보스·적별 패턴 라이브러리나 복수 적 조합 시스템은 아직 없습니다.

## 6. 접촉과 후속 시스템 연결

`CombatProjectile.contact(recipient)` → 실행기 → runner의 접촉 신호는 미래 피해 수신기의 경계입니다. 현재 접촉 시 투사체는 퇴장하지만 **HP 감소·피격 연출·사망은 없습니다**. 전투 플레이어는 충돌 layer 값 2, 벽은 1, 투사체는 layer 값 4/mask 값 2를 사용합니다. 숫자는 비트마스크 값이며 인스펙터의 레이어 번호와 혼동하지 않습니다.

후속 Q/E 시스템은 단계·살아 있는 대상·범위·조건을 검증하고 **실제 효과 적용 뒤에만** `notify_player_action_applied()`를 호출해야 합니다. 메뉴 열기·취소·무효 대상만으로 소비하지 않습니다. E 시간 UX는 구현 전에 사용자와 결정해야 합니다.

전투 결과 처리기는 개별 적/조우 결과와 중복 반영을 별도로 다루고 세계 상태·성장·필드 재등장에 전달해야 합니다. 현재 `development_exit_requested`는 승리·E 해결·도주가 아니며 `WorldState`를 변경하지 않습니다. HP·Q/E·타깃 선택·결과 확정·사망/체크포인트는 아직 미구현입니다.
