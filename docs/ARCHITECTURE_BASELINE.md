# DAEMONISM 기획·아키텍처 기준

갱신일: 2026-10-16. 근거와 실행 검증의 차이는 [문서 안내](README.md), 최신 검증 범위는 [구현 현황](IMPLEMENTATION_STATUS.md)을 따릅니다.

## 1. 사용자 확정 방향

- **[확정]** Godot 4.7.2, GDScript, Forward+, Windows PC / Steam용 싱글플레이 2D 탑다운 판타지 RPG. 한 회차 약 30시간을 목표로 합니다. 이전 Compatibility·WASD·10시간 목표는 폐기됐습니다.
- **[확정]** 겉보기에는 밝으나 비밀이 있는 세계, 고유한 이름·과거가 있는 주인공, 세계의 미스터리가 중심입니다. 선택·조사·관계·전투 결과가 후속 사건과 엔딩에 영향을 줄 수 있습니다. 구체적인 주인공·지역·사건·엔딩은 미정입니다. 과거 AI의 설정 제안은 정식 세계관이 아닙니다.
- **[확정]** 보이는 필드 적과 조우하면 독립 전투 장면으로 전환합니다. 강제 조우도 수용하되 반드시 처치를 요구하지 않습니다. 일반 적과 보스는 전투 기반을 공유합니다.
- **[확정]** 방향키로 이동합니다. 적 공격 단계에는 이동과 쿨타임이 있는 **무적 없는 대쉬**로 회피하며 Q/E를 사용할 수 없습니다. 일반적인 다수 적 조우도 하나의 공동 행동 단계를 사용합니다.
- **[확정]** 공격 단계는 시간 경과 또는 지정 패턴 시퀀스 완료로 종료합니다. 공동 행동 단계의 가변 N초 안에 살아 있는 적 한 명을 지정해 Q 또는 E 한 번을 실제로 완료합니다. 완료 또는 시간 초과 뒤 다음 공격 단계로 전환합니다. N은 고정 9초가 아닙니다.
- **[확정]** Q는 사거리 제한이 있는 즉시 마법 타격입니다. 적 HP 0은 처치입니다. Q의 사거리는 E보다 길다는 방향이며 구체 수치는 미정입니다. 사거리를 방해되지 않게 보여주는 UI가 필요합니다.
- **[확정]** E는 조사·대화·설득·조건부 행동 등을 수용합니다. 메뉴 열기·탐색·선택·실행은 하나의 제한시간 안의 행동입니다. 메뉴를 열었다는 이유로 행동을 소비하지 않습니다. 느려 보이는 연출의 선호와 실제 시간 정책은 구별합니다.
- **[확정]** 상단 감소 게이지로 행동시간을 표시합니다. 실제 시간은 전투 시스템이, 표시는 UI가 담당합니다. 숫자 표시는 개발용이며 정식 필수 사항은 아닙니다.
- **[확정]** 처치·E 해결·도주·미해결은 구별합니다. 전체/지역 집계와 중요한 인물·사건의 개별 기록을 구별하고, 모든 일반 적에게 깊은 영구 서사를 강제하지 않습니다. 재등장 규칙은 지역·적·사건별로 달라질 수 있습니다.
- **[확정]** 처치에 따른 공격적 성장은 숨겨진 마족 영혼 흡수와 관련됩니다. 성장 공식과 E 보상은 미정이며 임의로 대칭 보상을 만들지 않습니다. 세계 상태·전투 결과·성장 결과는 분리합니다.
- **[확정]** 수동 저장은 여러 슬롯의 진행 복원, 체크포인트는 사망 후 부활을 위한 별개 시스템입니다. 체크포인트 활성화가 수동 슬롯을 자동으로 덮어쓰면 안 됩니다. HP 0 → 사망 연출 → 게임오버 → 키 입력 → 활성 체크포인트 부활 흐름을 따릅니다.

## 2. 개발용 선택과 미정 사항

**[개발용·사용자 선택]** 이번 대쉬 입력은 Space(`combat_dash`)입니다. 최종 대쉬 키·타깃 변경 키·재시작 키는 미정입니다. 공격 3.5초·행동 6초, 아레나 크기, 이동/대쉬/투사체 수치와 도형은 최종 밸런스·픽셀 규격이 아닙니다.

**[개발용·잠정 동작]** 현재 전투 플레이어는 공격 단계와 행동 단계 모두에서 이동/대쉬할 수 있습니다. 사용자가 확정한 것은 공격 단계의 이동/대쉬이며, **행동 단계의 조작 허용 정책은 아직 미정**입니다. 필드 플레이어는 변경하지 않았고 대쉬를 추가하지 않았습니다. 필드/전투 능력·성장 공유도 결정하지 않았습니다.

실제 구현 전에 사용자 판단이 필요한 사항:

1. E 메뉴·대사 중 실제 제한시간 진행, 시간 배율, 연출과의 관계.
2. 사망 시 지역·적·플레이어·성장 상태 중 유지/복구할 범위.
3. 필드와 전투의 능력·스탯 공유 규칙, 행동 단계의 이동/대쉬 정책.

피해·사거리·대쉬 수치, 시야·해상도·픽셀 규격, 성장 공식, 콘텐츠 명칭은 필요 시 정하며 현재 값에서 추론하지 않습니다.

## 3. 기존 아키텍처 독립 재검토

기존 AI의 설계를 정답으로 취급하지 않고 실제 역할과 의존관계로 평가했습니다. 현재 저장소는 초기 규모이며, 장편 RPG의 콘텐츠·저장·분기 체계를 완성한 상태가 아닙니다.

| 선택 | 장점 | 현재 근거에서의 문제 | 판단 |
| --- | --- | --- | --- |
| 기존 구조 그대로 유지 | 동작하던 필드·저장·조우의 회귀 위험이 작음 | 빈 전투 화면에 이동·패턴·HP·UI를 계속 붙이면 조립과 규칙이 한곳에 모임. 외부 시퀀스 완료에 실행 주기 식별이 없으면 늦은 신호가 다음 단계를 진행시킬 수 있음 | 그대로 유지하지 않음 |
| **부분 재설계** | 동작하는 전환·콘텐츠 Resource·단계 코어를 보존하면서 실행 책임을 분리할 수 있음 | 새 경계를 실제 실행·회귀 검사로 검증해야 함 | **채택** |
| 전체 재설계 | 공통 모델을 처음부터 통일할 수 있음 | 현재 결함은 국소적이며 E 시간·사망 복구·성장·공유 규칙도 미정. 지금 전체 프레임워크를 만들면 가정이 고정되고 기존 동작 재검증 비용이 큼 | 현 단계에서는 근거 부족 |

**[기술 결정]** 기존 `GameRoot`, 필드 조우, `WorldState`/`SaveManager`, `CombatDirector`의 역할을 보존합니다. 전투 화면은 조립만 담당하게 하고, 아레나·전투 전용 플레이어·패턴 정의/실행기를 분리합니다. 감독에는 공격 주기 토큰과 재진입 방어를 추가해 실행 중단·재시작·늦은 완료 이벤트를 처리합니다. 이는 최종 기술 구조의 영구 동결을 의미하지 않습니다.

## 4. 현재 책임과 상태 경계

| 구성 | 소유하는 책임 | 소유하지 않는 것 |
| --- | --- | --- |
| `core/game_root.gd` | 타이틀/필드/전투 전환, 일시 보관한 필드 복원. 물리 콜백의 조우 요청은 지연 처리 | 승패 판정, 성장, 결과의 세계 반영 |
| 필드 씬·`PatrolEnemy` | 필드 이동/카메라, 순찰/접촉, 지역·배치 문맥을 담은 조우 요청 | 전투 인스턴스 생성·전투 단계 실행 |
| `EncounterDefinition` Resource | 안정적인 조우 콘텐츠 ID, 적 종류 목록, 시간/패턴 참조 | 적별 현재 HP, 선택 대상, 실행 중 타이머 |
| `EncounterRequest` RefCounted | 이번 조우의 정의 참조, `region_id`, `spawn_id` | 저장 파일, 영구 결과 |
| `CombatScene` | 감독·아레나·패턴·HUD의 신호 연결, 개발용 복귀 | 공격 알고리즘, 피해 계산, 세계 상태 변경 |
| `CombatDirector` / `AttackPhaseGate` | 공동 단계·N초·1회 행동 소비 / 공격 종료 조건 | 적 이름별 분기, 투사체 생성, Q/E 효과 |
| `CombatArena` | 경계와 벽, 전투 플레이어 배치, 아레나를 보는 고정 카메라 | 필드 카메라, 전투 결과 |
| `CombatPlayer` / `PlayerMotionSettings` | 전투 이동·대쉬·충돌 / 편집 가능한 수치 | 필드 능력, 성장, HP, 무적 |
| `AttackPatternDefinition` / 실행기 | 편집 가능한 패턴 설정 / 예고·투사체·종료 수명 관리 | 세계 영속 상태, 플레이어 피해 정책 |
| `WorldState` | 플래그·카운터·중요 결과의 메모리 상태와 스냅샷 | 완성된 조건/효과·중복 결과 적용·재등장 정책 |
| `SaveManager` | 버전 1 JSON 슬롯, 등록 섹션 검증 후 복원, 미등록 섹션 보존 | 현재 맵/위치·성장·전체 진행 저장, 체크포인트 |

콘텐츠 Resource는 여러 실행에서 공유할 수 있으므로 실행 중 HP·잔여시간·현재 선택 등을 기록하지 않습니다. 실행 상태는 해당 전투 인스턴스에 두고, 영속 상태는 명시적으로 확정한 결과만 저장 계층에 전달해야 합니다. 현재 실제 전투 결과 전달 경로는 미구현입니다.

## 5. 장편 RPG로 확장할 경계

- 조우 정의·지역·필드 배치·적 종류·전투 중 적 개체는 다른 식별자입니다. 지금의 `enemy_ids` 목록은 적별 런타임 HP나 다수 적 선택 체계가 아닙니다.
- 패턴은 공통 실행기를 재사용하거나 명시적인 사용자 정의 실행기 씬을 연결합니다. 보스 이름을 감독의 조건문에 추가하지 않습니다. 다수 적 조합은 우선 사전 설계한 조우 데이터로 다루며 자동 사회 시뮬레이션을 전제하지 않습니다.
- Q/E는 단계와 대상·범위·조건을 검증하고 효과를 적용한 뒤 감독에 완료를 알리는 별도 시스템으로 연결합니다. E 옵션의 조건/효과 처리는 향후 이야기 시스템과 경계를 정하되 아직 범용 언어·퀘스트 프레임워크를 만들지 않습니다.
- 결과 처리기는 개별 적 결과와 조우 결과를 구별하고, 한 사건의 중복 적용을 막은 뒤 세계 상태·성장·필드 재등장 정책에 각각 전달해야 합니다. 현재의 개발용 복귀는 이 경로를 타지 않습니다.
- 저장은 위치/진행·성장 등 실제 소유 시스템이 생길 때 섹션과 버전 이행을 추가합니다. 현재 버전 1 검사는 버전 이행 구현을 뜻하지 않습니다. 체크포인트는 별도 복구 정책을 정한 뒤 연결합니다.

새 시스템은 실제 사용 사례와 검증을 동반해 추가합니다. 확장 가능성을 위해 현재 미정인 기획을 임의로 구현하거나, 아직 필요하지 않은 범용 프레임워크를 선제 제작하지 않습니다.
