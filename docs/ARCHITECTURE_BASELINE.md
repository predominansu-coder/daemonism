# DAEMONISM — 기술 아키텍처 및 결정 기준

**갱신일:** 2026-10-15  
**근거:** FANTASY 인수인계 문서, 이 대화의 최신 사용자 결정, `2daemonism.zip`의 코드, 이후 제공한 Step 03 코드.  
**주의:** 이 문서는 기획/기술 기준이며 실제 Godot 실행을 대신하지 않는다.

## 1. 사용자 결정 [확정]
- 게임명: **DAEMONISM** (이전 작업명 FANTASY에서 변경). Godot **4.7.2**, **Forward+**, Windows/Steam 목표.
- 한 회차 약 **30시간**(다회차 별도)의 2D 탑다운 스토리 판타지 RPG.
- 겉으로 밝아 보이나 비밀이 있는 세계; 이름과 과거가 있는 주인공; 세계의 미스터리; 선택·조사·관계·전투 결과에 따른 복합 분기.
- **필드 이동 입력은 방향키(↑ ↓ ← →)**. 이전 WASD 규칙을 대체한다. 전투 중 이동 역시 현행 방향키 결정을 기준으로 후속 상세 입력을 정한다.
- 필드에 보이는 순찰 적과 조우하면 **별도 전투 장면**으로 전환한다.
- 일반 적은 공동 공격 단계와 공동 행동 단계를 반복한다. 공격 중 이동·무적 없는 쿨타임 대쉬 가능, Q/E 사용 불가.
- 공격 종료는 시간 경과 또는 패턴 시퀀스 완료 신호. 이후 가변 **N초** 동안 살아 있는 적 하나를 지정하여 **Q 즉시 마법 피해** 또는 **E 메뉴 선택·실행 1회**. 시간 초과 시 행동 없이 다음 공격 단계. N은 고정 9초가 아니다.
- 일반 적/보스는 공통 전투 코어 사용. 적 조합·특수 보스의 규칙은 개별 데이터/확장점으로 수용.
- **적 HP 0 = 처치**. 처치, E로 해결, 도주, 미해결은 구별한다.
- 세계 반응 범위: 총 처치 수 및 지역별 집계 등 넓은 기록 + 특정 인물·사건의 깊은 분기. 모든 일반 적에게 상세한 개별 이력은 요구하지 않음.
- 지역·적·사건에 따라 필드 적의 재등장 방식은 다를 수 있음.
- 처치에 따른 공격적 성장(사거리·피해 등)은 이야기상 숨겨진 마족 영혼 흡수와 관련. 성장 공식이나 대칭되는 E 보상은 미정. E 해결과 도주 사이에 큰 성장 격차를 강제하지 않음.
- **수동 저장 파일**과 **사망 후 부활 체크포인트**를 분리한다. 체크포인트가 기존 수동 저장 파일을 임의로 덮어쓰지 않는다.
- 플레이어 HP 0 → 사망 효과·연출 → 게임오버 화면 → 키 입력으로 활성 체크포인트에서 재시작.
- 행동 제한시간 N은 **전투 화면 상단 감소 게이지**로 표시한다. 숫자 타이머 병행은 확정 아님.
- 시스템은 향후 콘텐츠·특수 규칙·예외를 추가해도 가능한 한 기존 공통 기능을 보존하도록 역할·데이터·연결 규칙을 분리한다.

## 2. 아직 확정하지 않은 것 [미정]
- 성장 공식·레벨 상승 조건·처치 보상 세부 수치·E 해결의 구체적인 성장 효과.
- Q/E 실제 사거리 및 피해·대쉬 이동량·속도·쿨타임·HP·전투 공간 및 픽셀/해상도 규격.
- E 메뉴와 대사 표시 중 **실제 제한시간 처리** 및 슬로모션 연출 관계.
- 타깃 변경 키, 대쉬 키, 게임오버 화면 재시작 키.
- 사망 후 어떤 적/지역/플레이 상태를 유지·초기화할지, 체크포인트의 정확한 활성화/부활 규칙.
- 세부 세계관·NPC 대사·지역 구성·보스 이름·엔딩 조건.

## 3. 현재 코드의 시스템 책임 (실제 구현 확인과 향후 설계를 구분)
- `core/game_root.gd`: 타이틀 → 필드 → 전투 장면 전환. 원래 필드 인스턴스를 메모리에 보관하고 개발용으로 되돌린다. 물리 신호 콜백에서는 `call_deferred()`로 전환을 예약한다. **실제 전투 결과 적용은 아직 없음.**
- `actors/player/`: 공통 플레이어 씬과 방향키 이동/카메라. 현재 도형·맵 격자는 임시 표현.
- `actors/enemies/patrol_enemy.*`: 필드 순찰, `Area2D` 감지, 조우 요청. 개별 적의 스토리·전투 AI는 아직 없음.
- `systems/encounters/encounter_definition.gd`: `Resource` 기반 조우 ID, 적 종류 목록. Step 03 적용 시 `CombatTiming` 참조가 추가됨.
- `systems/encounters/encounter_request.gd`: 지역·필드 배치 ID 등을 포함한 실행 시점 조우 문맥. 콘텐츠 정의와 구분.
- `systems/world_state/world_state.gd`: 플래그·카운터·주요 결과의 기본 저장 형태. 사건 중복 적용 규칙이나 완성된 조건/효과 시스템은 아님.
- `systems/save/save_manager.gd`: 등록된 섹션의 JSON 수동 저장/복원 기반. **게임 전체 상태 저장 완성은 아님**. 체크포인트와 별개.
- Step 03 **적용 시 추가**: `CombatTiming`(시간/종료 설정), `AttackPhaseGate`(공격 단계 종료), `CombatDirector`(공격↔행동 단계 전환), `CombatScene` 상단 게이지. 실제 공격 패턴·Q/E 효과는 여전히 없음.

## 4. 식별자와 결과 처리 원칙
- `encounter_id`(조우 콘텐츠), `enemy_id`(적 종류), `spawn_id`(필드 배치 개체), `region_id`(지역)를 구분한다.
- `dev.*` 데이터는 개발 확인용이며 정식 세계관/밸런스가 아니다.
- 개별 사건 및 조우 결과는 **고유하게 한번 반영**되도록 향후 결과 처리 시스템에서 중복을 막아야 한다.
- 처치 집계·특수 적 상태·필드 배치 상태를 섞지 않는다.
- 시스템 데이터는 저장 파일 버전과 연결하되, 오래된 세이브와 새 콘텐츠의 호환성은 별도 설계·검증 대상이다.

## 5. 사용자가 직접 보고한 실행 검증 [실행 확인]
- 세계 상태의 수동 저장 및 Godot 재실행 후 불러오기: 성공(테스트 데이터 기준).
- 타이틀 → 방향키 필드 이동, 카메라 표시: 성공.
- 필드의 순찰 적 접촉 → 전투 화면 진입: 성공.
- 물리 콜백 중 충돌 노드 제거 경고: `GameRoot` 지연 호출 수정 이후 **사라졌다고 사용자 보고**.
- **Step 03 공격/행동 단계 전환 및 N 게이지:** 개별 코드 전달됨. 사용자의 실행 성공 보고는 아직 없음.

## 6. 다음 구현의 명확한 순서 [제안·작업 계획]
1. Step 03을 Godot에서 실행해 타이머·게이지 정상 여부 확인.
2. 공통 전투 플레이어(방향키 이동·무적 없는 대쉬)와 공격 패턴 실행기/피격 판정 연결.
3. 공격 단계 종료 조건(일반 적 시간, 보스 시퀀스), 복수 적 대상 선택, Q/E 실행 계약 연결.
4. 조우 결과 객체(처치/E 해결/도주/미해결)와 세계 상태의 **중복 없는 적용**, 필드 복귀/재등장 규칙 연결.
5. 게임오버·체크포인트 부활을 수동 세이브와 분리해 구현.
6. 실제 콘텐츠와 다회차/분기에 대응하는 저장 확장·버전 이행 검증.

구체적인 E 시간 정책·사망 후 유지 상태처럼 **구조에 영향을 주는 결정은 해당 구현 전에 사용자에게 요청**한다. 이미 정해진 확장 원칙을 다시 질문하지 않는다.
